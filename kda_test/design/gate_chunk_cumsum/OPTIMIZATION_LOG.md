# OPTIMIZATION_LOG: gate_chunk_cumsum

## 第一轮优化（消除不支持）

### 问题

目标 CASE (B=1, T=16384, H=96, K=128) 下，grid 展平后为 98304，超过 NPU AI Core 上限 65535，导致 kernel 无法执行。

### 根因

3D grid = (cdiv(K, BS), num_chunks, B*H)，其中 BS=32 时 cdiv(K,BS)=4，num_chunks=cdiv(T,BT)=256，B*H=96，展平 4×256×96=98304 > 65535。

### 方案

将 BS 从 32 增大到 64，使 cdiv(K,BS) 从 4 降为 2，展平 grid 降为 2×256×96=49152 ≤ 65535。BS=64 时 tile 大小 BT×BS=64×64=4096 elements，fp32 tile 占用 16384 bytes，远小于 UB 192KB 限制。

### 修改内容

**文件**: `src/gate_kernel.py`

| 行 | 修改前 | 修改后 |
|---|--------|--------|
| 62 | `_DEFAULT_BS = 32` | `_DEFAULT_BS = 64` |

### 优化前后对比 (第一轮)

#### 目标 CASE: B=1, T=16384, H=96, K=128

| 指标 | 优化前 | 优化后 |
|------|--------|--------|
| grid | (4, 256, 96) | (2, 256, 96) |
| 展平 grid | 98304 (>65535 ❌) | 49152 (≤65535 ✅) |
| 精度 max_diff | N/A（不支持） | 1.22e-3 ✅ |
| triton 耗时 | N/A | 4.32ms |
| torch_npu 耗时 | N/A | 12.25ms |
| speedup | N/A | 2.83x ✅ |

### 是否解决不支持问题
✅ **是** — grid 展平从 98304 降至 49152，低于 65535 上限。

### 全量回归验证
15/15 case 全部 PASS，所有 case 精度 max_diff < 1e-2。

## 第二轮优化（性能调优）

### 问题

BS=64 时 grid=(2,256,96) 展平 49152，虽然不超过 65535 但仍有大量 program (49152 个 block)。每个 block 只处理 64×64=4096 个元素，存在调度开销。

### 方案

将 BS 从 64 增大到 128，使 cdiv(K,BS) 从 2 降为 1，展平 grid 降为 1×256×96=24576。BS=128 时 tile 大小 BT×BS=64×128=8192 elements，fp32 tile 占用 32768 bytes，仍远小于 UB 192KB 限制。

grid 降为 (1, 256, 96) 后，展平 24576 ≤ 65535，且 block 数减少一半，每 block 处理元素数翻倍，提升了计算密度。

### 修改内容

**文件**: `src/gate_kernel.py`

| 行 | 修改前 | 修改后 |
|---|--------|--------|
| 65 | `_DEFAULT_BS = 64` | `_DEFAULT_BS = 128` |

**文件**: `kda_test/design/unified/bench.py`

| 行 | 修改前 | 修改后 |
|---|--------|--------|
| 275 | `_cdiv(K, 64)` | `_cdiv(K, 128)` |

### 优化前后对比 (第二轮)

#### 目标 CASE: B=1, T=16384, H=96, K=128

| 指标 | BS=64 (第一轮) | BS=128 (第二轮) |
|------|---------------|---------------|
| grid | (2, 256, 96) | (1, 256, 96) |
| 展平 grid | 49152 | 24576 |
| tile 元素数 | 4096 | 8192 |
| 精度 max_diff | 1.14e-5 | 1.14e-5 ✅ |
| triton 耗时 | ~4.06ms | ~1.85ms |
| torch_npu 耗时 | ~12.75ms | ~12.81ms |
| speedup | ~3.14x | **~6.93x** ✅ |

### Speedup 大幅提升的原因分析

1. **Block 数减半**: 49152 → 24576，减少了 program launch 和调度开销
2. **每 block 计算密度翻倍**: 每个 program 处理 8192 个元素而不是 4096 个，计算/访存比更高
3. **S 维无竞争**: cdiv(K,128)=1，即 S 维仅一个 tile，无跨 tile 通信或重复加载
4. **num_warps 影响小**: 1-8 warps 在 BS=128 下性能接近 (1.83-1.93ms)，说明瓶颈不在 warp 级并行度

### 全量回归验证

15/15 case 全部 PASS，所有 case 精度 max_diff < 1e-2，且所有 case speedup > 1.0x。

### 是否收敛

- 目标 CASE speedup ~6.93x，远超 >2.0x 目标
- 所有回归 case PASS
